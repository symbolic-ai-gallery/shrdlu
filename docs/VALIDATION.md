# 验证记录

遵照“不做过度测试”的要求，本次只验证界面重构和机械臂动作涉及的路径，没有重复整套测试或开展性能基准。

## 本次定向检查

- TypeScript 严格检查、Vite 生产构建和 `git diff --check` 通过。
- 执行 3 个测试：完整 43 轮英文流程及几何断言、清障与抓放阶段及持物偏移、双连杆在可达位置的长度约束。全部通过，其余 19 个已有测试未重跑。
- 浏览器运行 `Pick up the red cube.`：先完成绿色棱锥的接近、下降、夹紧、抬升、搬运、放下、松开、收回，再抓取红色立方块。记录可见阶段变化，并查看三维画面。
- 搬运过程中暂停，后续观察时仍保持暂停阶段；继续后完成剩余动作。
- Chromium 视口模拟：390×844 的页面高 844px，输入框底部 822px；390×480 的页面高 480px，输入框底部 458px；1440×900 的页面高 900px，输入框底部 872px。三种尺寸均无页面横向溢出，世界与对话同屏。短视口模拟不等于真机软键盘验证。
- Base UI 菜单可以通过键盘和模拟触摸打开，显示物体、语言、导出、显示设置、演示及重置操作。触摸检查修正了测试浏览器自身 80% 缩放造成的输入坐标偏差。
- 查看移动端入口页首屏，背景介绍和进入实验的入口正常显示。

## 界面依据

参考 [Vercel Web Interface Guidelines](https://vercel.com/design/guidelines)、[shadcn/ui](https://ui.shadcn.com/docs) 和 [Base UI Menu](https://base-ui.com/react/components/menu)：精简常驻操作、辅助功能按需展开、输入框保持在可见区域、移动输入字号 16px、主要触控目标 44px、提供焦点样式和手势之外的相机按钮。组件仍使用用户指定的 Base UI。
